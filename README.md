# Деловой журнал

Мобильная PWA для малого бизнеса. Пока это оболочка: обзор, календарь, клиенты, финансы и аккаунт. Запись на интервалы, учёт клиентов, оплат и долгов появятся на следующем этапе.

## Локальный запуск

Рекомендуется Node.js 22.x (не ниже 22.13) и npm.

```bash
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Без переменных окружения все четыре раздела доступны, а на экране «Аккаунт» показана инструкция по подключению. Пример прямой ссылки: `http://localhost:5173/#/calendar`.

## Подключение Supabase

1. В Supabase создайте проект. Возьмите **Project URL** и **Publishable key** из окна **Connect** или настроек API. Для старого проекта допустим публичный ключ `anon`. Не используйте `service_role`, секретный ключ или строку подключения PostgreSQL в переменных `VITE_*`: эти значения видны в браузере.
2. Скопируйте `.env.example` в `.env.local`, задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`, затем перезапустите Vite. Проверьте, что включены вход по Email и Data API со схемой `public`.
3. Примените миграцию к этому же проекту (см. ниже). В **Authentication → Users** создайте тестового пользователя с почтой и паролем и подтвердите его почту. Саморегистрации в интерфейсе нет.
4. Откройте `/#/account`, войдите, сохраните имя и перезагрузите страницу. Сессия восстановится; данные профиля загружаются из Supabase.

## Миграции Drizzle

```bash
cp db/.env.example db/.env
# В db/.env задайте DATABASE_URL выбранного проекта.
npm run db:migrate
```

Возьмите строку **Direct connection** из окна **Connect** в Supabase; если сеть не поддерживает IPv6, используйте **Session pooler**. Перед каждой миграцией сверяйте project ref в строке подключения. Если `DATABASE_URL` уже экспортирована в оболочке, она имеет приоритет над `db/.env`; снимите её через `unset DATABASE_URL`, если хотите использовать файл. `.env.local` и `db/.env` не попадают в Git.

`db/schema.ts` описывает `public.profiles`, связанный с `auth.users`. Запись создаётся при первом сохранении имени. Миграция настраивает права и RLS: чтение, вставка и изменение доступны только для собственной строки; анонимному пользователю таблица недоступна. При изменении схемы выполните `npm run db:generate -- --name=название`, проверьте новый SQL и сохраните его вместе с `db/migrations/meta/` в Git. Генерация и сборка фронтенда не подключаются к БД. Для существующего проекта не заменяйте рабочую таблицу `profiles` вслепую — сначала проверьте её схему.

## Импорт в Vercel

1. **Add New → Project** → импортируйте Git-репозиторий. Выберите **Vite**, **Root Directory** оставьте корнем (`.`), **Node.js Version** — `22.x`. В `vercel.json` заданы установка `npm ci`, сборка `npm run build` и выходной каталог `dist`.
2. В **Project → Settings → Environment Variables** добавьте обе публичные переменные отдельно для каждого окружения:

   | Окружение | `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` |
   | --- | --- |
   | **Preview** | Данные тестового проекта Supabase или без переменных для гостевого режима. |
   | **Production** | Данные рабочего проекта Supabase. |

3. После изменения переменных пересоберите нужное окружение. Не добавляйте `DATABASE_URL` в Vercel. Ни Preview, ни Production не запускают миграции: их применяют вручную, отдельно к каждой базе. Не используйте рабочий Supabase для Preview, если тестировщики не должны обращаться к рабочим данным.

## Проверка сборки и офлайн-режима

```bash
npm run typecheck
npm run build
npm run preview
```

Откройте `http://localhost:4173`. Манифест — `/manifest.webmanifest`, иконки — `/icons/journal.svg`, `/icons/icon-192.png`, `/icons/icon-512.png`, service worker — `/sw.js`. Worker работает в production-сборке на HTTPS или localhost. После его активации в первый онлайн-визит отключите сеть: четыре вкладки и перезагрузка по прямой ссылке продолжат работать. При обновлении сборки новая версия кэша активируется после закрытия старых вкладок приложения.

Обзор и вкладки не загружают код аккаунта или SDK Supabase. Worker кэширует только оболочку и известные статические файлы. Вход и работа с профилем требуют сети; ответы Auth и Data API не сохраняются в Cache Storage.

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты собирают и запускают production-версию без ключей и проверяют размеры панели, прокрутку, навигацию, отложенную загрузку аккаунта и офлайн-запуск. Для проверки реального входа используйте свой проект Supabase.
